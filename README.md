# みやび AIライティングスタジオ

40代・50代・60代以上の女性に向けた「みやびのnote」の記事企画・執筆・保存を支援する日本語アプリです。自分の経験や考えを生かし、AIの下書きを選んで手直ししながら記事を作ります。既存のPythonアプリは残しています。

**第3段階まで実装**：手動の記事管理、テーマ5案、SEOタイトル5〜10案、記事構成・本文のAI生成、みやび文体変換・AI文章校正・重複チェックが使えます。APIキーなしでも手動編集・保存・出力は動作します。

## Windowsで開く（ダブルクリック）

1. Python公式サイトから **Python 3.11以上（3.12推奨）** をインストールします。「Add python.exe to PATH」を選んでください。
2. GitHubの `miyabi-writing-studio-stage3` ブランチの「Code → Download ZIP」で取得し、ZIPを右クリックして「すべて展開」します。
3. 展開したフォルダーの中の **`start_windows.bat`** をダブルクリックします。拡張子が非表示の場合は `start_windows` と表示されます。ZIP内ではなく展開先で実行してください。
4. 初回は仮想環境と必要パッケージを導入するため、インターネットに接続して数分お待ちください。黒い画面は閉じないでください。
5. ブラウザーが開きます。開かないときは黒い画面に表示されるLocal URLをブラウザーで開きます。初回のメールアドレス入力は空欄のEnterで進めます。
6. 終了時は記事を保存してから黒い画面で `Ctrl+C` を押します。次回も `start_windows.bat` をダブルクリックします。

ランチャーは必要パッケージの初回導入と、依存定義が変わった際の再導入を行います。PowerShellの設定変更は不要です。エラーが出たら、画面を閉じる前に内容を控えてください。

## PowerShellでインストールする場合

エクスプローラーで `app.py` のあるフォルダーを開き、アドレス欄へ `powershell` と入力するとその場所でPowerShellを開けます。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

実行ポリシーで仮想環境の有効化が拒否された場合は、ポリシーを変えず以下で起動できます。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

ポート使用中の場合は末尾に `--server.port 8502` を追加します。Pythonが見つからなければインストール後にPowerShellを開き直します。`python` の代わりに `py -3.12` で仮想環境を作ることもできます。

## 第1・第2段階からの更新・記事の引き継ぎ

1. 全記事を保存してアプリを停止します。
2. 古いフォルダーとデータをバックアップして残し、新しいZIPを**別のフォルダー**に展開します。
3. 古いフォルダーの `data` を新しいフォルダーへコピーします。新しい保存先に記事がある場合は上書きしないでください。データを合体する機能はありません。
4. `.env` を作っていた場合はローカルで新しいフォルダーへコピーします。既存のファイルを不用意に上書きしないでください。
5. 新しい `start_windows.bat` で起動します。

保存先を `MIYABI_DATA_DIR` で変えている場合は、その設定を新しい `.env` に引き継いでください。相対パスは新しい `app.py` があるフォルダー基準です。必要に応じて同じ絶対パスを指定します。第1・第2段階と同じSQLiteのテーブルをそのまま使い、既存記事を削除・移行しません。旧アプリとの同時起動は避けてください。

## APIキーとモデルを設定する

AIを使う場合だけ設定してください。**ChatGPTの有料プランとは別に、OpenAI APIの利用料金がかかります。**

1. [OpenAI APIキー管理画面](https://platform.openai.com/api-keys)でキーを取得し、OpenAI側の支払い・利用枠を確認します。
2. **`configure_api_windows.bat`** をダブルクリックすると、既存の `.env` を開きます。まだなければ `.env.example` から作ります。
3. メモ帳の `OPENAI_API_KEY=` の右側へご自身のキーを記入し、保存します。実際のキーはソース・GitHub・チャットに貼らないでください。
4. アプリを停止して再起動します。

手動で `.env.example` を `.env` にコピーして設定しても構いません。Windowsで `.env.txt` にならないよう注意してください。空欄のキーはAI無効として扱います。既にある環境変数は `.env` より優先されます。

モデルの既定値は `OPENAI_MODEL`（初期値 `gpt-4.1-mini`）です。「AI利用設定」でそのセッションだけのモデル変更もできます。Responses APIとJSON SchemaによるStructured Outputsに対応し、ご自身のプロジェクトで利用可能なモデルを指定してください。モデルアクセスの可否はAPI呼び出し時に判定されます。

APIキーの値は画面・ログ・送信プレビューに出しません。AI結果や記事DBにも保存しません。`.env` はGit対象外です。

## AI記事づくりの使い方

左側の **「AI記事づくり」** を開きます。「作業する記事」は新しい記事か保存済みの記事を選べます。既存記事の備考はAIへ送りません。編集画面に未保存の下書きがある場合はそれを元に開始します。その後の編集画面の変更とは自動同期しません。

1. 「AI利用設定」でAPI利用を有効にします。
2. **テーマ企画**：ジャンル、想定読者、悩み、伝えたいこと、目的、キーワードを入力。「送信内容を確認」で今回の送信データ全文を表示します。料金と内容を確認してチェックすると、生成ボタンが使えます。テーマ5案から選ぶとタイトル画面へ引き継ぎます。
3. **SEOタイトル**：5〜10案のタイトル・実際の文字数・検索意図・魅力・改善ポイントを表示します。候補選択後もタイトルは手で修正できます。手動タイトルから構成へ進むこともできます。SEO評価は参考であり検索順位は保証しません。
4. **記事構成**：H1、導入、H2・H3、要点、まとめ、文字数配分と6項目の参考点検を生成します。「新規・再生成」「一部修正」を選べます。一部修正では元の構成と修正したい箇所を入力します。生成された構成を編集し「構成を確定」すると本文へ進みます。AIの部分修正が意図どおりかご自身でも確認してください。
5. **本文執筆**：全文、導入、指定H2・H3、まとめ、既存文章の続き、箇条書きの文章化の6モードから選びます。文字数の目安は200〜6000文字。実際の文字数が一致する保証はありません。
6. 経験フォームに「経験したこと」「困っていたこと」「どう考えたか」「試したこと」「伝えたいこと」を記入します。未入力の経験は創作させず、プレースホルダーや質問として返すよう指示しています。AIが指示を守っているか確認してください。
7. 生成本文を修正して「本文を置き換える」か「末尾に追加」で採用します。全文の置き換えは確認チェックが必要です。導入・部分・続きの結果は自動挿入しません。適切な位置への配置は手で編集できます。
8. 「記事編集へ反映」の確認をすると、タイトル・読者・ジャンル・キーワード・検索意図・構成・採用本文を編集欄に反映します。同じ項目にある未保存の内容は置き換わります。ハッシュタグ・備考・ステータス・公開情報は保持します。
9. **編集画面の「記事を保存」まで押してください。** 生成・採用・反映だけではDBへ保存しません。

条件やモデルを変えると送信確認は無効になります。生成条件が変わった過去の候補は表示を残しますが、ボタンでの採用を止めます。必要なら新条件で生成するか手で内容をコピーしてください。生成失敗時も以前の候補と保存済み記事は維持します。

AIの入力・候補・経験フォーム・モデルの一時設定は同じブラウザーセッション内で保持し、終了・再読み込み後は復元しません。結果はJSON、採用本文はMarkdownで退避できます。必要な本文・構成などは記事として保存してください。JSONファイルを再取り込みする機能はありません。

### 送信内容・費用・情報の確認

- AI生成ボタンを押したときだけ、表示した指示・素材・モデル・出力上限等を公式 `https://api.openai.com/v1/responses` へ送ります。API認証にはキーを使いますが、本文素材には含めません。
- 全記事の一括送信は行わず、記事の備考や無関係の本文も送りません。経験フォームなど、今回指定した素材は送信対象です。不要な個人情報は取り除いてください。
- [API料金表](https://openai.com/api/pricing/)を確認してください。金額の見積り機能はありません。出力上限はトークン数で、文字数や料金そのものではありません。
- タイムアウトは60秒、自動再送は無効です。タイムアウトでもサーバー側で処理が進み、費用が発生している場合があります。再生成はご自身の判断で行ってください。
- `store: false` で応答の保存を依頼しない設定ですが、OpenAI側のログ・保持についてはOpenAIのポリシーに従います。
- 外部検索や事実調査は行っておらず、結果は **「未検証」** と表示します。AIの体験・数値・出典をそのまま信用せず、公開前に確認してください。健康・美容・お金の効果や結果は断定しないよう注意を表示します。

### APIエラーのとき

キーの認証エラー、モデル・権限の問題、利用上限・残高不足、接続失敗、タイムアウト、不完全・形式不正の回答を日本語で表示します。外部エラーの生データは表示しません。入力と以前の生成結果、保存済みの記事は維持します。キー変更後はアプリを再起動してください。

## 第3段階：文章を整える・校正・重複チェック

左側の「みやび文体変換」「AI文章校正」「重複チェック」を使います。編集画面の「本文を校正・確認する」からも進めます。対象の記事を選ぶと、編集画面の未保存の下書き（なければ保存済み記事）を読み込みます。新しい文章を直接入力して使うこともできます。

**3つの画面で作業中の本文を共有します。** 選択記事・作業内容は画面移動中は保持しますが、再読み込み・アプリ終了後の復元はできません。AI記事づくりや編集画面とは自動同期しません。必要なら退避してから「編集内容を読み込み直す」を使ってください。この操作では確認チェックの後に、作業中の本文・候補・履歴を破棄します。一度記事を保存してから再び校正を始める場合も、最新の内容を読み込み直してください。

### みやび文体変換

1. 本文と、6つの文体モードから1つを選びます（やさしく温かい／親しみやすく自然／共感を重視／少し楽しく明るく／落ち着いた大人の文章／読者を引きつける導入文）。
2. 送信内容と料金を確認して変換します。導入文モードも入力した文章の範囲を整えます。
3. 変更前と変更後を左右で比較します。変更後は自由に修正できます。
4. 意味・事実・数字・実体験が変わっていないことを確認し、「修正を採用」を押します。
5. 「元に戻す」で直前の採用前に戻せます。採用後に本文を手動で変更している場合、その変更を消さないよう取り消しを止めます。必要な部分を手動で修正してください。

意味・主張・経験・出典を勝手に足さないよう指示していますが、AIの内容を保証するものではありません。必ず本人の確認を行ってください。原文・モード・モデルなどを変えると、古い候補は採用できなくなります。

### AI文章校正

以下の10項目を確認し、問題のある箇所を最大40件表示します。

1. 誤字脱字
2. 不自然な日本語
3. 同じ言葉の繰り返し
4. 同じ内容の重複
5. 長すぎる文章
6. 読みにくい表現
7. 見出しと本文の不一致
8. 断定的すぎる表現
9. 不安をあおる表現
10. 根拠が必要な記述

修正前・修正候補・理由を確認して、**「この修正を採用」を1件ずつ**押します。すべてを一括置換しません。引用の完全一致と、同じ引用が出る順番を元の本文で照合するため、同じ文が複数ある場合も指定箇所だけを直します。重なった範囲の修正、引用が一致しない修正、採用後に手動編集した本文への古い修正は適用しません。「元に戻す」で採用を逆順に取り消せます。

根拠確認が必要な指摘は自動採用せず、事実や出典を確認してから手動で修正します。健康・美容・お金に関しては効果を断定しない注意を表示します。すべての指摘は外部情報が**未検証**です。指摘がなくても文章や事実の正しさを保証しません。

### 重複チェック：無料のローカル確認

**APIキー不要、外部送信なし**で、本文内の繰り返しと、保存済みの過去記事との文字列の重なりを確認できます。

- 空白・句読点・全角半角を整え、文字3個の並びの共通度で候補を表示します。対象記事自身は過去記事の比較から除外します。
- 表示のしきい値は40〜100%で選べます。表示の%は最も共通する箇所の目安であり、記事全体の重複率ではありません。
- 本文内の比較は12文字以上の文の先頭300文まで。過去記事の抜粋比較も先頭300文までです。全文の共通度は10万文字以内の記事全体で比較します。現在の本文が10万文字超なら分けて確認し、10万文字超の過去記事は除外してIDを表示します。
- 内部の候補・過去記事の候補はそれぞれ上位20件まで表示し、件数と確認範囲を表示します。本文や比較記事が変わると前回の結果であることを通知します。
- **文字列の一致による参考情報**です。言い換えた同じ意味の文章を必ず見つけるものではなく、盗用判定やインターネット上の検索も行いません。共通した定型文も候補になるため、文脈を見て判断してください。自動削除はしません。

### 重複チェック：過去記事とのAI比較（任意・従量課金）

意味・切り口の重なりを参考確認したい場合に使います。比較先の過去記事を**1〜5件、自分で選びます**。最初に各記事の先頭3000文字を抜粋として表示するので、比較したい箇所へ編集してください。抜粋を用意した後に元の記事が更新された場合は通知し、読み直す操作も用意しています。

送信プレビューで現在の本文と、選んだID・タイトル・抜粋を確認してからAPI実行します。未選択の記事や備考、全記事一覧を自動送信しません。引用が送信した本文・抜粋と一致しないAI回答はエラーにして採用しません。結果は最大15件で、重なる可能性のある引用・理由・別の切り口を表示します。自動で本文を書き換えません。指摘なしでも、送信した抜粋以外やインターネット全体を確認したという意味ではありません。

### 第3段階の結果を記事へ保存する

「本文の退避・記事保存へ」でMarkdownをダウンロードできます。AIの生の確認結果はJSONでも退避できます（変更後を手動編集した内容は作業本文へ採用してからMarkdownで退避してください）。再取り込みは実装していません。

**「選択した記事の編集欄の本文に反映します」にチェック →「本文を記事編集へ反映」→編集画面で「記事を保存」**の順で保存します。反映するのは本文だけで、記事のタイトル・ハッシュタグ・備考・公開情報は保持します。新しい記事の場合は編集画面でタイトルを付けて保存してください。

作業開始後に編集画面の本文が変更されている場合は、両方を消さないよう反映を止めます。別のセッションでDBが更新された場合も保存時の競合チェックを引き継ぎます。元の記事が削除されても作業本文は退避できます。

## 手動の記事管理・出力

- 「新しい記事」から仮のタイトルでも保存できます。対象読者、キーワード、検索意図、構成、本文、タグ、ステータス、公開日、note URL、備考を管理します。
- 「記事一覧」は検索・ステータス絞り込み・並べ替え・編集・複製・確認付き削除に対応します。複製時は公開日・URLを空にし「アイデア」へ戻します。
- 編集中の入力は画面移動時に一時保持します。未保存の下書きには左側に戻るボタンが出ます。再読み込み・終了の前に保存してください。
- 保存失敗時は入力を残して通知します。保存済みデータはトランザクションで保護し、別タブで更新された記事への古い内容の上書きを防ぎます。競合時は入力をダウンロードしてから再読み込みしてください。
- 「出力・投稿準備」では保存済みのタイトル・本文・ハッシュタグをMarkdown／テキスト出力できます。編集画面では未保存の内容も出力できます。備考・検索意図・構成メモは出力しません。
- コピー用欄は `Ctrl+A` → `Ctrl+C` でコピーできます。この欄の編集は記事へ保存されません。
- Markdownの見出し、太字、リンクの基本的な記法をテキスト出力で変換します。表など全記法の変換ではありません。
- noteへの貼り付け・投稿は手動です。自動投稿は行いません。

## 保存先・バックアップ

既定の保存先は `app.py` と同じフォルダーの `data/miyabi.sqlite3`。作成日・更新日は日本時間です。`.env` の `MIYABI_DATA_DIR` で保存先を変更できます。Windowsでも `/` 区切りのパスを使えます。

```dotenv
MIYABI_DATA_DIR=C:/Users/YourName/Documents/MiyabiData
```

保存先の設定だけではデータは移動しません。保存先を変更する前にアプリを停止し、元のファイルをバックアップしてから新しい場所へコピーします。

バックアップ画面は第4段階で追加予定です。現在は全記事を保存しアプリを停止した後、`miyabi.sqlite3` を日付付きの安全な場所へコピーしてください。復元時も停止し、現在のファイルを退避してから戻します。Markdown出力は全項目のバックアップではありません。

`.env`・SQLiteデータ・APIキーはGitに登録しない設定です。独自の保存先やバックアップも公開フォルダーに置かないでください。本アプリは個人のPC向けで、ログイン機能はありません。個人情報を含む状態でインターネットへ公開しないでください。

## 開発・検証

```powershell
python -m unittest discover -s tests -v
```

テストは一時DBと模擬APIを使い、課金や実際の記事への変更は発生しません。SQLite CRUD・永続化・競合・失敗時の保護、全AIワークフロー、6執筆モード、部分構成修正、6文体モード、1件ずつの校正採用・取り消し・引用位置・修正範囲の重なり、ローカル／AI重複確認、送信確認の無効化、秘密の除外、認証・上限・通信エラー等を検証します。実OpenAI SDKのHTTPトランスポートも模擬応答に置き換えてリクエスト形式を検証しています。

検証環境はLinux / Python 3.12です。**Windows実機および実キーでのAPI呼び出しは未検証**です。モデルの利用権限や実際の生成品質は、Windows側でキーを設定した後に確認してください。
